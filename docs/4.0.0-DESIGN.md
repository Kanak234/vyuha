# VYUHA 4.0.0 — Design brief (PRD + TRD + UI notes)

Source of truth for the 4.0.0 update. Written before implementation, updated after.

## 1. Problem (from real tester feedback, 2026-09-28)

A tester used VYUHA, found no bug, and asked for two things:

1. **"A scrolling bar for increment and decrement in sizes"** — movement (orbit) felt fine,
   but there was no visible control for size. Verified cause: zoom existed only as mouse
   wheel / pinch (invisible), node size could not be changed at all, and the only sliders
   sit in the timeline bar, which CSS hides below 820 px — the usual width of a panel
   opened beside the editor.
2. **"Highlight the specific line of code when the user double taps a sphere."** Verified
   cause: a single click already moved the cursor, but (a) nothing was highlighted, and
   (b) the line was stored per *frame* only and helper-library programs never sent one,
   so for most programs the click did nothing.

## 2. Goals / non-goals

Goals
- An always-visible **view dock** with a **Zoom** slider and a **Size** slider, each with
  + / − buttons and a live value readout, in both renderers (data-structure and network).
- **Double-click / double-tap** any node → the editor jumps to its source line, centres it
  and **highlights the whole line**.
- Every node can carry its **own** source line; the common sources fill it automatically.

Non-goals (4.0.0)
- Go, C and C++ helper libraries do not auto-report lines (Go is untestable on the build
  machine; C/C++ would need macro wrappers around every call). For C/C++, *Debug Visualize*
  already reports lines per stack frame.
- Networks emitted *by a running program* (not a `.vyuha.json` spec) have no source anchors.

## 3. Exact behaviour

| Action | Result |
|---|---|
| Single click on a node | Opens the inspector (unchanged). Data-structure view: **no longer moves the editor** (it stole scroll position while exploring); the inspector shows the node's line and "double-click to open". Network spec view: unchanged (`vyuha.revealOnClick`). |
| Double-click / double-tap (same node, ≤ 400 ms, ≤ 10 px) | Editor opens the run file (or spec file), selects + centres the line, whole-line highlight + overview-ruler mark. |
| Node has no line | A small hint chip explains why; nothing else changes. |
| Highlight lifetime | Until the user moves the cursor with mouse/keyboard in that editor, edits it, or another line is revealed. |
| Zoom slider | Up = closer. Logarithmic, so it feels even across the range. Mouse wheel / pinch / fit / reset move the slider too (two-way sync). Readout in % of the default distance. |
| Size slider | 0.4× – 2.5×, applies to spheres, bars, halos, arrowheads and label offset; layout spacing unchanged. Starts at `vyuha.nodeSize`. |
| Keys | `+` / `-` zoom, `]` / `[` size. Ignored while typing in an input. |

Line priority for a node: `node.line` → `frame.line`.

## 4. Where lines come from

| Source | Line |
|---|---|
| Auto-visualize (source read) | each function/loop/branch/print node → its own line |
| Debug Visualize (Python, C/C++) | each stack-frame node and its locals → that frame's current line (gdb: only frames in the user's file) |
| Python helper `vyuha.py` | call site in the main script, captured automatically (explicit `line=` wins) |
| JS helper `vyuha.js` | call site in `require.main`, automatically (explicit `line` wins) |
| Java helper `Vyuha.java` | call site in the file that holds `main`, automatically |
| Raw `@vyuha` JSON | `"line"` on the frame and/or on any node |

## 5. Architecture / files

- `media/viewcontrols.js` (new) — shared dock + double-tap detector + hint chip. Renderers
  register `{min,max,home,getDist,setDist,setSize}`; dock routes to the awake renderer.
  No own `requestAnimationFrame`: renderers call `sync()` from their loops.
- `media/ds.js`, `media/main.js` — register with the dock, apply node size, detect double-tap,
  post `revealLine` (ds) / `reveal` (net).
- `src/highlight.ts` (new) — one `TextEditorDecorationType`, reveal + highlight + auto-clear.
- `src/runview.ts`, `src/panel.ts`, `src/extension.ts` — message plumbing.
- `src/protocol.ts` — `VNode.line`. `src/codegraph.ts`, `src/debugviz.ts` — fill it.
- `lib/vyuha.py`, `lib/vyuha.js`, `lib/Vyuha.java` — automatic call-site line.
- `package.json` — 4.0.0, `vyuha.nodeSize` setting, two theme colours.
- `media/logo-mark.svg` — KP watermark (Kanak's standing rule since 2026-09-22).

## 5b. Decisions added during implementation

- **Watermark source.** The original `logo-mark.svg` (from `KANAKq/kanak-coder-1.5b-GGUF`
  on Hugging Face) is 20 KB of sampled polyline points. Re-drawn as a 1.1 KB vector with
  the same geometry: straight strokes and the P bowl copied exactly, the orbit fitted as an
  ellipse (max deviation < 0.2 units on the 64-unit grid).
- **Watermark is inlined as a `data:` URI** in `viewcontrols.js`, not loaded by URL: a
  webview resource URL is cross-origin and would taint the GIF canvas (`getImageData`
  throws). A test asserts the inlined copy equals `media/logo-mark.svg`.
- **Watermark sits beside, not inside, the title** — both renderers overwrite the title's
  `textContent` on every update.
- **Add-on:** key `0` / double-click on the size readout resets size to 1.0×.

## 6. Acceptance criteria

1. Dock visible at every panel width ≥ 320 px, in both modes.
2. Dragging Zoom changes camera distance; wheel changes the slider.
3. Size 2.0× doubles sphere scale; bars keep sitting on the floor.
4. Double-click posts exactly one reveal with the node's line; a single click posts none.
5. Frames from the Python/JS/Java helpers carry the caller's line with no code change.
6. All pre-existing tests still pass; new tests cover 2–5.


## 7. 4.1.0 follow-up (same design, gaps closed)

Verified problems from 4.0.0's non-goals and from inspection:

| Gap | Evidence | Fix |
|---|---|---|
| Java + helper would not compile | `java BinarySearch.java` beside `Vyuha.java` → `cannot find symbol: Vyuha` (reproduced) | `src/runner.ts` compiles both with `javac -d <temp>`; `javaMainClass()` reads the package |
| C/C++/Go frames had no line | 4.0.0 non-goal | `lib/vyuha.h` macros + `vyuha_close()`, `lib/vyuha.hpp` `VYUHA_HERE` default args, `lib/vyuha.go` `vyuhaCallerLine()` |
| No GIF in network view | only `ds.js` had `exportGif` | `media/main.js` recorder in the render loop, `bGif` button, `panel.ts` + `extension.ts` plumbing |

Decisions: the network recorder copies frames inside the render task instead of
turning on `preserveDrawingBuffer` (which would slow every normal frame); C macros
are defined after the functions so they cannot rewrite the definitions; C++ uses a
default argument, not a macro, because a macro named `array` would break
`std::array`.
